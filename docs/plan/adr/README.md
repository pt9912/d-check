## Konventionen

- ADRs sind nach `Accepted` **immutable** (siehe Baseline-Regelwerk
  `modul-04-adrs.md`) — hier zusätzlich maschinell erzwungen (`make adr-check` /
  [ADR-0016](0016-adr-immutable-gate.md)).
- Schärfungen entstehen als neue ADR mit `Supersedes ADR-NNNN`. Der Status der
  abgelösten ADR wird `Superseded by ADR-NNNN` — **in ihrer Datei**, nicht nur
  in diesem Register; die Datei ist die Quelle der Wahrheit, dieser Index die
  Sicht. Vierstellig, wie der Dateiname.
- Bei `Accepted`: diesen Index aktualisieren (Status, Datum). Neue ADRs werden
  **am Ende** der Tabelle ergänzt — sie ist chronologisch **aufsteigend** nach
  Nummer.
- Jede ADR deklariert im `**Schärft:**`-Feld *aufwärts*, welche Spec-Stelle
  sie verbindlich macht (Baseline-Regelwerk `grundlagen-referenz-richtung.md`
  §Referenz-Richtung (SDP); nie das Lastenheft) — als **Kennung**
  (`SPEC-<NNN>` in der Spezifikation, `ARC-<NNN>` in der Sicht,
  `<DC-ID>.<Buchstabe>` bei einer Verfeinerung; Link auf die Überschrift bzw.
  die Sektion), ersatzweise als Abschnitt, wo die Sektion keine Kennungen
  vergibt. **Prozess-ADRs ohne Spec-Stratum tragen `—`.** ADRs mit Status
  `Accepted` vor welle-80 bleiben auf ihren `§`-Ankern (immutabel) — zwei
  Formen, eine Regel
  ([`MR-000`](../../../harness/conventions.md#mr-000--baseline-aussage)).
  Beide an einem Beispiel: die **neue** nennt die Kennung als Linktext und
  zeigt damit auf den Abschnitt, in dem die Zeile steht — etwa `SPEC-<NNN>`
  verlinkt auf `§4. Grund- und Fehler-Codes`. Die **alte** nennt nur den
  Abschnitt — etwa `spec/architecture.md` `§2` —, weil ihre ADR vor der Vergabe
  `Accepted` wurde und damit immutabel ist.
- **Dateiname** (Repo-Zusatz zur Vorlage): `<NNNN>-<kurzer-titel-kebab>.md`,
  vierstellig, zero-padded.
