# Eine Semantik-Änderung wird nur im Dokumentkörper nachgezogen, ihre Ränder bleiben stehen

**Sub-Area:** `*`

Historie-Zeilen, Index-Einträge, Konsequenz-Abschnitte, Entscheidungs-Protokolle
sind Prosa und darum gate-unsichtbar: `links`/`anchors`/`ids` prüfen die
Auflösung, nicht die Aussage. Der Rand referiert danach eine Fassung, die es
nicht mehr gibt, und wirkt dabei so belastbar wie der Körper. Ableiter: vor
dem Ändern einer Semantik ihre Spiegel per `grep` nach dem **alten**
Wortlaut auflisten — nicht aus dem Gedächtnis, und wo eine Aufzählung eine
Menge spiegelt, gehört sie an ihre Quelle gebunden statt in eine Liste
geschrieben.
